# data/

Two CSV files drive the whole project.

| File | One row per | Key columns |
|------|-------------|-------------|
| `hrrp.csv` | hospital **per condition** | Facility ID, Measure Name, Number of Discharges, Excess Readmission Ratio |
| `hospitals.csv` | hospital | Facility ID, Hospital Ownership, Hospital overall rating (stars) |

They join on **Facility ID** (CMS also calls it Provider ID).

## Where this data comes from

The real files are published openly by CMS on the Provider Data Catalog:

- Hospital Readmissions Reduction Program — https://data.cms.gov/provider-data/dataset/9n3s-kdb3
- Hospital General Information — https://data.cms.gov/provider-data/dataset/xubh-q36u

## Sample vs. real data

The CSVs committed here are **sample data** generated by `make_sample_data.py`.
They match the real CMS schema column-for-column and reproduce the same messy
bits (suppressed "Too Few to Report" values, footnotes, one row per condition,
missing star ratings, hospitals in only one file) so the pipeline runs with no
download. They are **not** real hospital numbers.

To run the analysis on the **real** CMS data instead:

```bash
python3 download_real_data.py   # overwrites the two CSVs with real CMS files
python3 clean.py
python3 run_analysis.py
```

Everything downstream (cleaning, SQL, dashboard) is identical — only the
contents of these two files change.

> **Before cleaning real data**, confirm the hospital id column is named
> `Facility ID` in both files. CMS has renamed it between releases; a mismatch
> is the single most likely thing to break the join. If it differs, update the
> two `read_csv` calls in `clean.py`.
